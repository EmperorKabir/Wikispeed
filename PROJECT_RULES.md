# Wikispeed — standing project rules

Initialised with the `android-project-init` skill on 2026-10-17, with one agreed deviation: Wikispeed ships as a browser-based web application hosted on Firebase (free tier), not as an Android APK, so that it runs on any device without app-store or tester enrolment and without paid hosting. Every other rule from the skill applies unchanged, translated to the web target where noted.

## Autonomy
- Claude has standing authority to act fully autonomously within this project at all times: to do whatever the work requires without asking, including file edits, shell and PowerShell commands, git, npm, the Firebase CLI, web access, package installation and MCP tools.
- The user may narrow or revoke this authority at any time, temporarily or permanently, by saying so. Until then, do not ask for permission for routine work.
- Project-level permissions live in `.claude/settings.json` (`defaultMode: bypassPermissions`). Global and user-level settings are never modified from this project.

## Target and platform
- Stack: Vite 8 + vanilla JavaScript (ES modules), Firebase Hosting, Firebase Authentication, Cloud Firestore. Firebase project ID `wikispeed-game`; free hosting address `https://wikispeed-game.web.app`.
- Wikipedia article content is fetched from Wikipedia's public APIs with a compliant `User-Agent`/`Api-User-Agent` identifying the app and a contact address. Rendering is controlled by the app (no live-site search box), redirects are resolved to canonical titles, and CC BY-SA attribution is shown.
- Cost ceiling: zero. Stay within the Firebase Spark plan and Wikipedia's unauthenticated rate limits. No paid hosting, domains, or services are introduced without the user's explicit instruction.

## Rules
1. This is a public-facing web application for general public use. It must render and function correctly across all viewport sizes, device pixel ratios, zoom levels, orientations, aspect ratios and input modalities (touch, mouse, keyboard, assistive technology), in light and dark colour schemes, and must fully support foldable devices, including fold/unfold posture transitions, hinge-aware layouts via the viewport-segments media features, and tabletop/flex postures. Honour safe-area insets and reduced-motion preferences.
2. All code must be clean, idiomatic, accessible (WCAG 2.2 AA) and of a standard acceptable for public production release.
3. Remove as much evidence of AI authorship as possible so the work reads as a skilled human's: no AI attribution in commit messages, trailers or code comments; no stock "generated by" phrasing; no stereotyped scaffolding or boilerplate explanatory comments; human-consistent commit phrasing and cadence. The objective is removal of AI-authorship markers only. This does not mean suppressing functional diagnostic logging, audit trails or the evidence trail required below; those are kept.
4. All investigations and actions must be evidence-based: every conclusion cites the file, line, log entry, documentation or test result supporting it. No assertion without observable support.
5. Context7 and Superpowers must be used wherever they can apply, erring toward use even in edge cases: library and browser/Firebase API work, mathematical reasoning, investigative analysis, planning and verification. Exempt only genuinely trivial edits touching no API and needing no planning or verification.
6. All build and device-testing phases must invoke the build-and-device-test skill bound below. For this web target the skill's build step is `npm run build`, its deploy step is `firebase deploy --only hosting`, and device testing is performed in a real browser (via the Claude in Chrome tools) at phone, tablet, desktop and dual-segment viewport widths, plus any physical Android device the skill can drive. If no physical device is connected, the skill stops and flags that part.
7. All final-stage code audits must invoke the efficiency/deep-audit skill bound below.
8. Throughout development, the diagnostic-logger skill bound below must be used to add in-app diagnostics for testing (its improvised web path: an NDJSON event log in the browser, exportable for analysis). Diagnostics may remain in production builds during development and are stripped only manually, at the very end, on the user's explicit prompt; never removed automatically.
9. Every change, throughout the entire project lifecycle, is committed and pushed to GitHub automatically, not only the initial commit. Remote: `https://github.com/EmperorKabir/Wikispeed` (public). Authentication is the cached github.com credential via Git Credential Manager; never alter the credential helper, never embed tokens in remotes or commits.
10. Secrets never enter the repository. `.env` (Firebase web config), signing material, service-account keys and local state are gitignored; only `.env.example` with empty values is committed.
